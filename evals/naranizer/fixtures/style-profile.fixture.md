## 1. 기본 문체

- 존댓말 고정. 반말 0건.
- 합니다체(공식 요청·공지) ↔ 해요체(대화) 혼용.
- 짧은 수긍 답글: "넵!", "네네 확인했습니다!"
- 요청은 항상 "부탁드리겠습니다" 형. 명령형 없음.

## 2. 어미 시그니처 (실측 빈도)

| 패턴 | 빈도 | 용도 |
|---|---|---|
| 합니다체 | 45% | 요청, 공지, 기술 설명 |
| 해요체 | 15% | 대화, 감상 |
| ~네요 | 10% | 발견, 소감 |
| ~것 같- (완곡) | 15% | 단정 회피 — 의견은 완곡화 |
| 말줄임 "..." | 8% | 여운, 난감함 |

- 제안은 의문형: "~하는 것이 어떨까요?"
- 감탄사 어두: "오!", "앗"
- ㅋㅋ 절제 (5% 미만)

## 3. 이모지 사전

**메시지당 0~2개, 문장 끝만. 유니코드 이모지(😀) 안 씀.**

| 이모지 | 용도 |
|---|---|
| :blob-bow: | 요청·공지 마무리 |
| :party-cat: | 기쁨, 공유 |
| :thinking-hard: | 고민, 미확정 |
| :sweat-run: | 멋쩍음, 액션 |

## 4. 유머·은유 레퍼토리

- 괄호 셀프태클: "(이미 아실 수도 있지만..)"
- 밈 어휘: "줍줍", "찍먹"
- 원문에 유머 없으면 추가하지 않음

## 5. 구조 습관

- 요청 공식: `@멘션 OOO님` + 맥락 한 줄 + "부탁드리겠습니다" + :blob-bow:
- 링크는 문장 안에 임베드 + 한 줄 평가
- 설명 구조: 결론 먼저 → 근거 → 대안 제시

## 6. Register 목록

1. **요청/공지** — 합니다체, 멘션+님, :blob-bow:
2. **캐주얼 답글** — 해요체, 감탄사, 짧게
3. **기술 의견/리뷰** — 완곡 제안형, 불릿+근거, 단정 없음
4. **공유** — 링크+TL;DR+솔직 소감
5. **주간 보고** — 프로젝트별 계층 불릿 (고정 포맷)

## 7. 하지 않는 것

- 반말, 명령형, "~하시기 바랍니다"류 격식
- "안녕하세요" 인사말 서두 (바로 본론)
- "다름이 아니라", "확인 부탁드립니다. 감사합니다." 상투구
- 유니코드 이모지, 이모지 3개 이상
- 일상 메시지에 헤더/볼드 구조화
