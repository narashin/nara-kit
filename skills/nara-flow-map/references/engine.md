# 엔진 계약과 구성안별 데이터

스타터 `assets/flow-map.html`은 엔진과 데이터가 한 파일에 있다. `// ===== DATA` 와 `// ===== end DATA` 사이만 바꾸고 그 아래 엔진은 손대지 않는다. 엔진이 모자라면 데이터로 우회하지 말고 사용자에게 알린다. 엔진 수정은 이 스킬의 asset을 고치는 별도 변경이다.

## 데이터 블록

| 이름 | 내용 |
| --- | --- |
| `META` | `title`(탭과 머리말), `intro`(머리말 한 줄: 예시가 무엇인지, 카드·원통·규칙 칸이 무엇인지), `startTitle`, `startNote`(재생 전 설명) |
| `NODES` | 상자 목록. 좌표는 SVG 기준(기본 1400×830) |
| `PATHS` | `{ 이름: SVG path d }`. 선 하나가 화살표 하나 |
| `DASHED` | 확인하지 못한 경로 이름의 Set. 점선으로 그린다 |
| `VIEW` | `{ 이름: [x, y, w, h] }` 카메라 위치. `full`은 필수 |
| `CH` | 장 이름 배열. 타임라인의 묶음 |
| `STEPS` | 단계 배열. 아래 표 |

`NODES` 항목.

| 필드 | 뜻 |
| --- | --- |
| `type` | `box` 일반 상자, `cyl` 줄이 쌓이는 저장소, `gate` 통과/멈춤을 보이는 규칙, `frame` 묶음 테두리(내용 없음) |
| `stat` | 상자 아래에 상태 줄을 둔다. `setStat`이 쓰는 상자에는 필요하다 |
| `ghost` | 아직 없는 상자. 처음엔 흐리게 "아직 없음", `exist(id, true)`로 진해진다 |
| `rows` | 보이는 줄 수. `cyl`은 필수, `box`에 주면 제목 아래에 줄이 쌓인다(주인공 카드용) |
| `clock` | 시계 표시. 시간으로 깨어나는 상자 |
| `dashed` | 확인하지 못한 상자 |
| `color` | 왼쪽 막대 색. `--c-ext` 외부, `--c-core` 중심 서비스, `--c-store` 저장소, `--c-edge` 경계·큐, `--c-worker` 처리기, `--c-batch` 배치·화면 |

`stat`, `ghost`, `clock`, `rows`는 `box`와 `cyl`에만 준다. `frame`과 `gate`에 주면 데이터 오류다. 줄과 상태 줄이 겹치지 않도록 높이 하한이 있다: `box`는 `66 + rows×20`, `cyl`은 `90 + rows×20`, 상태 줄(`stat` 또는 `ghost`)이 있으면 22를 더한다. 모자라면 데이터 오류가 필요한 h를 알려 준다.

`STEPS` 항목.

| 필드 | 뜻 |
| --- | --- |
| `ch`, `view` | 장 번호(`CH` 인덱스), 카메라 이름(`VIEW` 키) |
| `trig` | 무엇이 이 단계를 깨웠나. `clockTrig: true`면 시계 색 |
| `title` | 이 단계에서 일어나는 일 한 문장 |
| `data` | 실려 가는 값(파란 칩) |
| `store` | 쌓이거나 바뀌는 곳(초록 칩) |
| `warn` | 확인 못 한 것 한 줄(노란 칩, `[미확인]` 포함) |
| `note` | 덧붙일 설명. 설명용 가정이면 여기 적는다 |
| `src` | 근거 `path:line` 또는 문서 링크. 화면 아래에 작게 보인다 |
| `run(ctx)` | 지도를 움직이는 함수. 아래 동사만 쓴다 |

`run` 안에서 쓰는 동사. 모두 `ctx`를 받는 것은 그대로 넘긴다.

| 동사 | 하는 일 |
| --- | --- |
| `await fly(path, label, ctx, { reverse, ok, dur })` | 이름표 카드가 선을 따라 이동. `reverse`는 거꾸로, `ok`는 초록 카드(응답) |
| `addRow(id, text, ctx, { key, disp })` | 저장소에 줄을 쌓는다. 같은 `key`는 덮어쓴다. `disp`는 지워질 값 색 |
| `setStat(id, text)` | 상태 줄 |
| `setGate(id, "eval" \| "pass" \| "block" \| "", text)` | 규칙 칸 상태 |
| `exist(id, true)` | ghost 상자를 진하게 |
| `clock(id, true)` | 시계 켜기 |
| `await merge({ from: [[path, label], ...], to: [path, label], pair: 1 \| 2 }, ctx)` | 짝 색 카드 여럿이 동시에 합류점으로 와서 하나로 합쳐진 뒤 `to`로 출발 |
| `await split({ from: [path, label], to: [[path, label], ...] }, ctx)` | 카드 하나가 갈림점에 와서 여러 장으로 나뉘어 동시에 출발 |
| `hot(id, ctx)` / `toast(x, y, text, ctx)` / `await sleep(ms, ctx)` | 강조, 잠깐 뜨는 말풍선, 기다림 |

나눠 보내기. 같은 데이터가 여러 곳에 동시에 가는 장면(이벤트 하나를 규칙 여럿이 각자 평가하는 것 같은)은 `split`으로 그린다. 들어오는 선을 한 곳에만 그리면 나머지 받는 쪽이 앞 상자의 결과처럼 읽힌다. 예시 스타터의 첫 판이 그랬고, 리뷰어가 "크기 검사 규칙이 통과와 멈춤으로 갈라지는 거냐"고 물었다. 규칙 하나의 결과에 따라 길이 갈리는 조건 분기는 아직 엔진에 없다. 필요하면 가지 않은 길을 `DASHED`로 그리고 note에 "멈춤이면 이쪽"을 적는다.

합치기. 데이터 둘 이상이 합쳐져 다음 출력이 되는 장면은 `merge`로 그린다. `from`의 경로는 모두 같은 점(합류점)에서 끝나고 `to` 경로가 그 점에서 시작해야 한다. 어긋나면 `merge`가 오류를 던진다. 합류점에는 상자가 없어도 되고, 끝점이 셋 이상 모인 점은 검사가 합류점으로 본다. 합류점으로 들어가는 갈래에는 화살촉을 붙이지 않는다. `pair`는 짝 색이고 한 지도에 둘까지(1 보라, 2 분홍)만 쓴다. 노랑(기본)과 초록(`ok`, 응답)은 짝에 쓰지 않는다. 합쳐질 카드는 출발할 때부터 같은 색이라, 관계없는 카드가 동시에 날 때도 짝이 먼저 보인다. 2026-11-13 비교에서 도형(세모·네모 반반)은 짝 색이 이미 하는 일을 반복해 빼기로 했다.

지킬 것. 점프는 앞 단계를 `ctx.instant`로 빠르게 다시 돌려서 상태를 만든다. 그래서 상태를 바꾸는 줄을 `if (!ctx.instant)` 안에 두거나 DOM을 직접 고치면 점프한 화면과 재생한 화면이 달라진다. `flowSelfCheck`의 restore가 이걸 잡는다.

## 구성안 세 가지

셋 다 같은 엔진, 같은 검사를 쓴다. 다른 것은 상자 배치와 카메라다. 2026-11-13 기준 실제로 만들어 평가받은 것은 지도뿐이고, 나머지 둘은 데이터 조합법만 있다.

- **지도 (기본)** — 시스템 전체를 공간에 펼친다. 같은 서비스에 속한 상자는 `frame`으로 묶고, 저장소는 `cyl`, 조건 검사는 `gate`로 둔다. 단계마다 카메라가 그 쌍으로 다가간다. "무엇이 어디에 있고 무엇이 무엇을 깨우나"가 요점일 때.
- **주인공 카드** — 데이터 하나(요청, 주문, 이벤트)를 주인공으로 둔다. 거쳐 가는 곳을 한 줄로 놓고, 화면 한쪽에 `rows`를 준 `box` 하나를 주인공 카드로 둔다. 단계마다 `addRow(카드, "...", ctx, { key })`로 붙은 값이 자란다. "이 데이터에 무엇이 하나씩 붙나"가 요점일 때.
- **장면별** — 장마다 캔버스의 다른 구역을 쓴다. 구역마다 그 장에 필요한 상자만 두고(같은 대상이 여러 장에 나오면 `alert_s1`, `alert_s2`처럼 장마다 id를 따로), `VIEW`도 장마다 하나씩 둔다. "장마다 따로 봐야 하는 장면이 있다"가 요점일 때.

## 자체 검사 결과

`await flowSelfCheck()`는 JSON을 돌려준다. `ok`는 아래 목록이 모두 비었을 때만 `true`다.

| 키 | 잡는 것 |
| --- | --- |
| `data` | id 중복, 모르는 type, 없는 view·장, cyl의 rows 누락. 이게 있으면 지도를 그리지 않는다 |
| `leftover` | `SAMPLE` 문구가 남음 |
| `through` | 선이 상자를 지나감(양 끝 8px 제외, frame 제외) |
| `dangling` | 선의 시작·끝이 어느 상자 가장자리에도, 합류점에도 닿지 않음(4px 허용) |
| `framing` | 단계의 카메라가 그 단계에서 날아가는 선의 양 끝 상자를 자름 |
| `orphan` | 어느 단계도 쓰지 않는 상자. 카드가 오가지도 않고 줄·상태·문이 바뀌지도 않는다 |
| `hidden` | 어떤 단계에서 상자가 숨겨짐 |
| `playback` | 처음부터 끝까지 실제 속도의 재생에서 난 오류, 끝나지 않은 재생 |
| `restore` | 점프한 결과와 빠른 재구성 결과가 다름, 또는 처음으로 되돌린 화면이 처음 열었을 때와 다름 |

함수가 없다고 나오면 스크립트가 문법 오류로 멈춘 것이다. 브라우저 콘솔의 첫 오류가 원인이다.

검사가 못 보는 것: 글자 겹침, 상자 안 글이 넘침, 색 대비, 이야기가 사실과 맞는지. 앞의 셋은 스크린샷으로, 마지막은 사실 목록과 대조해서 본다.
