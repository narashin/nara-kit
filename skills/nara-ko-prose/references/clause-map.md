# 조항별 모드 배정

fluent-korean 원문의 조항을 `repair` / `full` 중 어느 모드에서 적용할지 정한 표다. **조항 본문을 옮겨 적지 않는다** — 절 이름과 번호만 참조하고, 실제 문구와 예시는 실행 시점에 원문에서 읽는다. 원문이 지침 요약을 권장하지 않으므로 이 파일은 요약이 아니라 배정 기록이다.

원문 위치는 SKILL.md의 Rule Source 절을 따른다.

## 배정

| 원문 절·번호 | 요지 (식별용 한 줄) | repair | full | 배정 근거 |
|---|---|---|---|---|
| 동작 범위 1 | 외국어를 한국어로 번역하라는 지시가 아님 | O | O | 범위 한정 조항. 어느 모드에서도 지켜야 한다 |
| 동작 범위 2 | 코드에 속하는 텍스트는 적용 제외 | O | O | 제외 규정. Scope 표에 그대로 반영 |
| 동작 범위 3 | 고유명사·기술 용어는 정착 번역어 우선, 없으면 원어 | O | O | 명확성 조항이고 말투를 건드리지 않는다 |
| 동작 범위 4 | 사용자 메시지의 어조를 모방하지 않음 | **X** | O | `naranizer`의 목적이 사용자 말투 적용이다. repair에서 적용하면 개인 말투 변환이 통째로 취소된다 |
| 문장 단위 1 | 의미 있는 문장 성분 생략 금지, 관형격 `~의` 남용 주의 | O | O | 결핍 교정. 압축이 만든 대표적 결함 |
| 문장 단위 2 | 명사구·부사구·연결어미로 끝내지 말고 종결어미로 완결 | O | O | 결핍 교정. 원문이 헤더·목록을 스스로 제외하므로 그 제외를 따른다 |
| 구 단위 1 | 조사·어미 생략 금지, 부사·보조사·선어말어미·보조용언 활용 | O | O | 결핍 교정. repair의 중심 조항 |
| 구 단위 2 | 맥락에 적합한 한자어를 적극 활용 | **X** | O | 어휘 선택을 바꾼다. `nara-humanizer`가 "한자어 과다"를 결함으로 검출하므로 두 스킬이 서로를 되돌린다 |
| 구 단위 3 | 비유적 어휘로 일반 명사·동사를 대체하지 않음 | **X** | O | 어휘 교체를 요구한다. 개인 말투의 비유를 깎는다 |
| 구 단위 4 | 엠대시 자제, 콜론·접속사로 대체 | O | O | 문장부호 치환이며 어휘·말투와 무관하다. `nara-humanizer`도 같은 방향으로 잡으므로 충돌하지 않는다 |
| 추가 사항 | 서브에이전트 프롬프트·결과 전달에도 적용 | O | O | 적용 범위 확장 조항 |

## repair가 부분집합인 이유

분량을 줄이려는 것이 아니다. `X` 표시된 세 조항은 모두 **어휘 선택이나 어조를 바꾸는 조항**이고, 그 셋만 빼면 `naranizer`가 입힌 개인 말투와 `nara-humanizer`가 덜어낸 결과를 훼손하지 않으면서 명확성을 확보할 수 있다.

`full` 모드는 이 타협을 하지 않는다. 사용자가 직접 호출했다면 문체까지 원문 기준으로 맞추겠다는 뜻으로 읽는다.

## 파이프라인 위치

```
초안 생성 (nara-pr / nara-rfc / nara-adr / nara-publish-spec / nara-spec-revision)
  → naranizer  (개인 말투, 프로필 없거나 미설치면 스킵)
  → ko-prose repair  (명확성 수리, 규칙 원문 없으면 스킵)
```

ko-prose가 마지막이다. 명확성이 최종 판단을 갖되, 건드리는 범위가 좁아서 앞 단계를 되돌리지 않는다.
