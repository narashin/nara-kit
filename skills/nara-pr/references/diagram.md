# 구조 그림: 구성·흐름·상태가 바뀐 PR에 archify 그림을 넣는다

화면이 바뀌면 [화면 캡처](visual-capture.md)가 맡는다. 이 파일은 화면 밖의 변경, 그러니까 구성·아키텍처·흐름·상태가 바뀌어서 글 한 줄로는 안 읽히는 PR을 맡는다. 화면 변경 PR에 이런 변경이 함께 있으면 둘 다 한다. 화면을 캡처하지 못한 경우에 그림으로 대신하지는 않는다. 화면이 어떻게 보이는지는 구조 그림으로 나오지 않는다.

그림은 확인 화면 전에 만든다. 로컬에서 그리기만 하고 아무것도 올리지 않으므로 승인 전에 해도 된다. 업로드는 승인 뒤 [이미지 첨부](attach-images.md) 절차로 한다.

## 1. 그릴지 판정

`base...HEAD` diff에서 셀 수 있는 것만 근거로 쓴다. 하나라도 맞으면 그린다.

| 근거 | archify 유형 |
|---|---|
| 새로 생기거나 바뀐 호출·의존 관계가 모듈 셋 이상에 걸친다 | `architecture` (전후 비교가 필요하면 `compare`) |
| 요청·이벤트가 셋 이상의 구성 요소를 차례로 거치는 흐름이 생기거나 순서가 바뀐다 | `sequence` 또는 `workflow` |
| 상태 값이나 상태 전이가 추가·삭제된다 | `lifecycle` |
| 배포·설정 구조(서비스, 큐, 저장소, 환경 간 연결)가 바뀐다 | `architecture` |
| 테이블이나 관계(외래키)가 둘 이상 바뀐다 | `erd` |

여러 줄이 함께 맞으면 그림 하나로 고른다. 리뷰어가 물을 질문이 "누가 누구를 부르나"면 `architecture`, "어떤 순서로 지나가나"면 `sequence`다. 둘 다 근거 줄에 적는다.

그리지 않는 경우: 이름 변경, 파일 하나 안의 로직 변경, 위 근거가 하나도 없는 변경. "복잡해 보인다"는 근거가 아니다. 그리지 않을 때는 확인 화면에 아무 줄도 쓰지 않는다.

확인 화면에 판정 근거를 한 줄로 적는다: `그림: lifecycle · 주문 상태에 '보류'와 두 전이가 생김`. 사용자가 빼 달라고 하면 업로드하지 않는다.

## 2. 도구가 없을 때

- archify가 같이 설치돼 있지 않다(이 스킬 옆의 `../archify/SKILL.md`가 없다) → 그리지 않는다. 확인 화면에 `그림 후보: <근거> · archify 없음으로 건너뜀` 한 줄만 남긴다.
- 브라우저 도구(playwright 또는 chrome-devtools MCP)가 없다 → HTML까지는 만들 수 있지만 PNG를 못 뜬다. `그림 후보: <근거> · Unverifiable (브라우저 도구 없음)`으로 적고 HTML 경로만 알린다.
- 어느 경우든 이미지 링크나 자리표시를 본문에 넣지 않는다. PR 생성은 막지 않는다.

## 3. 그리기

archify의 [SKILL.md](../../archify/SKILL.md)와 저장소 근거 규칙(`references/repository-authoring.md`)을 따른다(같이 설치된 스킬 파일. 없으면 2절로 간다). PR용으로 바꾸는 값만 여기 적는다.

- 출력 폴더는 저장소 밖 임시 폴더로 정한다. 저장소에 `.archify/`를 만들지 않는다.
- 노드, 선, 상태는 전부 diff와 그 주변 코드에서 온 것만 쓴다. 그림을 채우려고 관계나 순서를 지어내지 않는다. 일부만 그렸으면 제목에 범위를 적는다(`결제 흐름 중 환불 부분`).
- `meta.locale: "ko"`, `meta.legend: { "mode": "hidden" }`. archify의 범례는 내부 분류라 PR 독자에게 소음이다.
- 줄(lane)과 노드는 판정 근거를 보여 주는 데 필요한 만큼만. PR 본문 폭(약 880px)으로 줄어들면 노드 아래 설명 글씨가 작아진다. 설명은 짧게 쓰고, 긴 내용은 본문 산문으로 뺀다.
- `finalize`가 통과해야 다음으로 간다. 실패하면 archify의 수리 절차를 따르고, 한도 안에 못 고치면 그림을 빼고 이유를 적는다.

## 4. PNG 뜨기

archify CLI에는 전체 그림을 PNG로 내보내는 명령이 없다. `visual-check`의 PNG는 1440×900 화면 한 칸이라 그림이 잘리고 툴바가 찍힌다. 그래서 그림 요소만 찍는다.

1. 결과 HTML 폴더를 `127.0.0.1`의 임의 포트로 띄운다(브라우저 도구는 `file://`을 막는다).
2. 페이지를 열고 떠 있는 컨트롤을 숨긴다: `document.querySelectorAll('.toolbar, .export-menu, .no-print').forEach(e => e.style.setProperty('display', 'none', 'important'))`.
3. `svg[data-layout-contract]` 요소만 device scale로 찍는다.
4. 서버와 페이지를 닫는다.
5. PNG를 직접 열어 본다. 잘린 곳, 겹친 라벨, 남은 툴바가 없는지 본다. 있으면 다시 찍거나 그림을 뺀다.

2026-10-30에 workflow 그림 하나로 이 순서를 실측했다(2212×2054 PNG, 툴바 없음).

## 5. 본문

`## 주요 변경` 바로 다음에 `## 구조` 절을 만든다. repo 템플릿이 있으면 변경 설명 헤딩 아래에 넣는다. 그림 앞에 그림이 무엇을 보여 주는지 한 문장, 그림 뒤에 읽는 법 한 줄을 쓴다. 그림이 안 보여도 산문만으로 뜻이 통해야 한다.

```markdown
## 구조
알림 발송이 이제 채널별 발송기로 나뉘고, 실패한 알림만 재시도 목록에 남습니다.

![알림 발송 경로](<link>)
굵은 선이 이번에 생긴 경로이고, 점선은 실패 시 재시도입니다.
```

receipt 한 줄: `그림 <n>장: <유형> · 근거 <한 줄> · finalize 통과`.
