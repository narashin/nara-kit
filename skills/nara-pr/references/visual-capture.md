# 화면 변경 캡처: 배포 환경과 로컬을 같은 화면으로 찍어 넣는다

diff가 화면 파일(컴포넌트, 페이지, 템플릿, 스타일)을 바꿨고 사용자가 이미지 경로를 주지 않았을 때 따른다. 이미지 경로가 주어졌으면 이 파일은 건너뛰고 [이미지 첨부](attach-images.md)로 간다.

캡처는 확인 화면을 띄우기 **전에** 한다. 기준 환경에서는 읽기만 하고 아무것도 올리지 않으므로 승인 전에 해도 된다. 업로드는 확인 화면에서 승인받은 뒤 attach-images.md 절차로 한다.

## 1. 켜는 조건

- 저장소에 `.claude/ui-diff/env.md`가 있고 `baseline_url`이 채워져 있다 → 묻지 않고 캡처한다. env.md를 채운 것을 동의로 본다.
- env.md가 없다 → 캡처하지 않는다. 확인 화면에 한 줄만 남긴다: `화면 변경 있음 · 캡처하려면 /nara-ui-diff로 .claude/ui-diff/env.md를 만드세요`. PR 생성은 막지 않는다.
- 브라우저 도구(chrome-devtools 또는 playwright MCP)가 연결돼 있지 않다 → 캡처하지 않고 `캡처: Unverifiable (브라우저 도구 없음)`으로 적는다. 이미지를 지어내거나 자리표시를 넣지 않는다.

env.md, `login.md`, `screens/*.md`의 형식은 [ui-diff 프로필](../../nara-ui-diff/references/profile.md)과 [드라이버 순서](../../nara-ui-diff/references/drivers.md)를 따른다(같이 설치된 스킬 파일. 없으면 env.md의 viewport와 로그인 항목만 읽고 진행한다).

## 2. 어느 화면을 찍나

`.claude/ui-diff/screens/*.md` 중 바뀐 컴포넌트가 보이는 화면의 `Entry`를 쓴다. 맞는 화면 파일이 없으면 확인 화면 전에 한 번 묻는다: `어느 화면에서 찍을까요? (경로 또는 URL)`. 바뀐 파일 이름이나 라우트 규칙으로 경로를 추측하지 않는다.

화면이 새로 생긴 경우(기준 환경에 그 화면이 없음)는 로컬 한 장만 찍고 `기준 없음: 새 화면`으로 적는다.

## 3. 기준 환경: 읽기만 한다

- 기본은 QA다. env.md `baseline` 항목의 `notes`에 prod라고 적혀 있을 때만 prod를 기준으로 쓴다.
- 허용: env.md의 로그인 절차, `Entry`의 이동과 탭·모달 열기, 스크롤, 대기.
- 금지: 데이터를 바꾸는 제출, 저장·삭제·승인 버튼, 기준 환경으로 가는 쓰기 요청. Entry가 그런 클릭을 요구하면 그 화면은 찍지 않고 이유를 적는다.
- viewport와 DPR은 env.md 값으로 양쪽을 똑같이 맞춘다(`emulate`로 DPR까지).

**배포본은 base 브랜치와 같은 코드가 아닐 수 있다.** 배포가 늦었거나 다른 변경이 먼저 나갔으면 두 이미지의 차이가 이 PR 때문이 아닐 수 있다. 그래서 이미지 이름은 역할(수정 전)이 아니라 출처로 단다. 배포 버전은 env.md에 버전 확인 방법이 적혀 있을 때만 읽고, 없으면 `배포 버전 미확인`으로 둔다.

## 4. 로컬

이 브랜치를 [로컬 캡처](../../nara-local-shot/SKILL.md) 방식으로 띄워 같은 화면, 같은 viewport로 찍는다(같이 설치된 스킬 파일. 없으면 env.md의 `local_dev_cmd`로 띄우고 `local_url`에서 찍는다). 이미 떠 있는 dev 서버가 이 브랜치의 코드인지 먼저 확인한다. 다른 브랜치에서 띄운 서버면 다시 띄운다.

## 5. 올리기 전에 이미지를 직접 본다

각 이미지를 열어 확인한다. 바뀐 부분이 실제로 보이는지, 화면이 로딩 중이거나 오류 화면이 아닌지 본다. 안 보이면 다시 찍거나 그 쌍을 빼고 이유를 적는다.

실제 사람 이름, 이메일, 전화번호, 고객 식별자가 보이면 캡처 **전에** 그 요소에 CSS blur를 주입하고 다시 찍는다(`el.style.filter = 'blur(6px)'`, 브라우저 안에서만 바뀌고 서버에는 아무것도 안 간다). 가릴 수 없으면 그 이미지는 올리지 않는다.

## 6. 확인 화면과 본문

확인 화면에 이미지 쌍마다 한 줄: 출처 둘, 화면, 이미지에서 보이는 차이. 로컬 파일 경로를 같이 적어 사용자가 열어 볼 수 있게 한다. 확인 화면에 올라온 이미지만 승인 한 번으로 업로드된다.

본문 표 헤더는 출처로 단다.

```markdown
| QA 배포본 (배포 버전 미확인, 2026-10-30 캡처) | 이 브랜치 (로컬 @ 1a2b3c4) |
|---|---|
| ![baseline](<link>) | ![local](<link>) |
| 정산 금액이 소수점 없이 보임 | 정산 금액이 소수점 둘째 자리까지 보임 |
```

receipt 한 줄: `캡처 <n>쌍: 기준 <env> (<host>) · 로컬 @ <short SHA> · blur <k>곳`.

## 7. 정리

이 실행이 연 브라우저 페이지와 이 실행이 띄운 dev 서버만 닫는다. 이미지 파일은 업로드가 끝날 때까지 남겨 둔다.
