# 마커 문법 (mini-DSL)

문서의 수치 옆에 출처를 **한 번** 선언하면, 이후 감사는 전자동·결정론적으로 돈다.

```
<수치> <!-- src: <file>.csv | <집계> [where <조건> [and <조건>...]] [/ <수>] -->
```

## 허용 집계

| 집계 | 형태 | 결과 |
|---|---|---|
| `count` | `count rows` | 필터 통과 행 수 |
| `distinct` | `distinct <col>` | 그 컬럼의 고유값 개수 |
| `sum` | `sum <col>` | 합 |
| `avg` | `avg <col>` | 평균 |
| `max` / `min` | `max <col>` | 최대 / 최소 |

`count`는 컬럼을 받지 않는다 (`count rows`만). 나머지는 컬럼이 필수다.

## 필터

`where <col> <op> <값>`, 연결은 `and`만. 연산자 `= != < > <= >=`.

양쪽이 숫자면 **숫자로** 비교한다 — `score>=100`은 문자열 비교("9" > "100")가 아니라 수치 비교다.

## 단위 환산

`/ <수>` 또는 `* <수>` 하나까지. `avg response_ms / 1000` → 초 단위.

## 거부되는 것 (해석하지 않고 에러)

| 입력 | 이유 |
|---|---|
| `users.csv (활성 사용자 수)` | 자연어 — "활성"이 `status=active`인지 `last_login` 기준인지 매번 달라진다 |
| `... join teams on id` | JOIN — 조인 의미를 추측하면 틀린 값을 자신 있게 낸다 |
| `... where id in (select ...)` | 서브쿼리 |
| `... where a=1 or b=2` | `or` — AND만 지원 |
| `median score` | 미지원 집계 |
| `count rows` (파일 없음) | 소스 미지정 |

거부는 `syntax_error`로 보고되고 **그 주장만** 격리된다. 나머지 주장 감사는 계속된다.

## 예외 선언

의도적으로 실측과 다른 값을 쓸 때(예: MVP 1차 범위만 다룸):

```
지원 상태 5종 <!-- src: status.csv | distinct code --> <!-- intentional: 1차 범위는 5종만 -->
```

판정이 `intentional`이 되어 교체 대상에서 제외되고, 사유가 리포트에 남는다.

## 판정 값

| 판정 | 뜻 | 후속 |
|---|---|---|
| `match` | 문서값 = 실측값 | 없음 |
| `mismatch` | 다름 | 교체 후보 (문서가 틀렸을 수도, CSV가 낡았을 수도) |
| `ambiguous` | 마커 앞에 숫자가 둘 이상 | **교체 안 함.** 마커를 그 수치 바로 뒤로 옮길 것 |
| `mapping_failure` | 파일·컬럼 없음, 필터 결과 0행 | 사람이 마커 수정. **0으로 대체 안 함** |
| `syntax_error` | 문법 밖 | 사람이 마커 수정 |
| `intentional` | 예외 선언됨 | 없음 |

`ambiguous`·`mapping_failure`·`syntax_error`는 모두 **미해결**로 집계되어 게시 게이트를 막는다.

## 마커 위치 규칙 (중요)

마커는 **그 수치 바로 뒤**에 둔다. 마커 앞 구간에 숫자가 둘 이상이면 어느 것이 주장인지 기계가 알 수 없어 `ambiguous`로 빠진다.

```markdown
활성 사용자 10명 <!-- src: ... --> (전체 50명 중)    ← 좋음
활성 사용자 10명 (전체 50명 중) <!-- src: ... -->    ← ambiguous
월 1,200건 <!-- src: ... -->                          ← ambiguous (천단위 콤마 = 숫자 2개)
```

한 줄에 마커를 여러 개 둘 수 있다. 각 마커는 **직전 마커 이후 구간**의 숫자만 본다.

## 띄어쓰기 규칙

단위 환산의 연산자는 **양옆에 공백**이 필요하다 (`avg ms / 1000`). 공백이 없으면 환산으로 보지 않는다 — 그래야 `where day=2026/01/02` 같은 필터 값이 잘리지 않는다.

## 비교 정밀도

문서가 쓴 소수 자릿수에 맞춰 비교한다. `2.0초`로 썼으면 소수 1자리까지만 본다 — 실측 `2.0004`도 일치로 본다. 정수로 썼으면 정확히 일치해야 한다.
