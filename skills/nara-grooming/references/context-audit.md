# rules·skills 영역 감사

rules 또는 skills 영역이 범위에 있거나, 사용자 교정이 지속 지침과 연결될 때만 읽는다. 출처: tiger-kit `tk-grooming` `references/persistent-context.md`·`discovery.md`·`instruction-economy.md`·`failure-paths.md` (`5e633e3`), 증류해 줄였다.

## 찾기

- **rules**: user `CLAUDE.md`와 그것이 `@`로 끌어오는 파일, `rules/*.md`(항상 로드), `references/*.md`(조건부, 필요할 때 Read), repo `CLAUDE.md`·`AGENTS.md`와 하위 디렉터리의 것. import와 디렉터리 상속을 먼저 풀고 나서 비교한다.
- **skills**: repo의 `skills/`·`.claude/skills/`·`.agents/skills/`, 설치본 `~/.claude/skills`·`~/.codex/skills`. 지금 호스트의 실제 경로만 쓴다. 호스트를 모르면 대상을 지어내지 않고 `Unverifiable`.
- 심링크는 실제 대상까지 푼다. 사용자의 설정 파일 다수가 dotfiles로 가는 심링크라, 링크 경로를 고치려 하면 쓰기가 거부되거나 엉뚱한 사본을 고친다.

## 소유 판정

경로, 링크 대상, 설치기 흔적(lock 파일, 매니페스트, 업데이트 메타데이터), 작성 이력을 합쳐 판정한다. 신호 하나로 결론 내지 않는다. 사용자 이력이 없다는 것이 vendor라는 증거도 아니다.

- 확인된 vendor 설치본 → `keep (vendor)`. 품질 소견만 적고 수정 제안은 하지 않는다.
- 사용자가 만든 저장소에서 설치된 사본 → 사본이 아니라 소스 경로를 대상으로 제안한다.
- 소유를 모름 → 수정 제안 전에 한 번 묻는다.

## 지속 지침의 증거 사슬

```
교정된 동작 → 지속 지침의 정확한 구절(경로:줄) → 현재 소유자의 정확한 구절(경로:줄) → 충돌
```

동작과 교정을 일반 규칙으로 바꿔 쓰지 않는다. 현재 소유자(설치된 현행 스킬 등)는 설치·버전 증거로 정한다. `stale override`는 낡은 구절이 현재 소유자와 충돌하고 관찰된 동작을 설명할 수 있을 때만이다. 최신성, 구체성, 로드 순서만으로는 안 된다.

## 지침 경제성

- description과 조건부 참조 링크는 컨텍스트 포인터다. 좋은 포인터는 무엇이 있고 어느 분기가 그것을 필요로 하는지 말한다. 절차 요약을 description에 넣으면 본문을 안 읽고 지름길로 쓰일 수 있다. 그런 구절은 정확히 인용하고, 라우팅에 필요한 가장 작은 판별어만 남기는 안을 낸다. 짧게 줄이는 것 자체가 목표는 아니다. 오판을 막으려면 긴 description이 맞을 수 있다.
- 패키지 버전, 디렉터리 목록, 도구 능력처럼 싸게 다시 조회할 수 있는 값을 지침에 박아 두었다면 캐시 후보다.
- 어떤 지침이 "효과 없음"이라는 주장은 그것을 뺀 실행이 같은 동작을 낸다는 비교가 있을 때만 쓴다. 문체, 줄 수, 토큰 절감은 증거가 아니다.
- 항상 필요한 권한·안전·경계 규칙은 본문에 둔다. 특정 분기에만 필요한 내용만 포인터 뒤로 옮긴다.
- 동작이 바뀌는 수정은 여기서 하지 않는다. 소유 스킬의 정확한 제안으로 남기고 `/nara-skill-forge`로 넘긴다.

## 실패 경로

| 상황 | 대응 |
|---|---|
| 경로 없음·읽기 불가 | 그 영역만 `Unverifiable`, 나머지는 계속 |
| 소유 불명 | 수정 제안 없음, `partial` + 소유 질문 하나 |
| 분류 후 vendor로 확인 | 모든 수정 동작을 `keep (vendor)`로 바꾼다 |
| 옮기거나 지울 대상을 다른 곳이 참조함 | 변경 없음, `keep` 또는 `tighten`으로 바꾸고 참조를 적는다 |
| 승인 후 대상이 바뀜 | 변경 없음, `partial` + 현재 증거로 새 제안 |
| 깨진 링크·git 판정 실패 | 그 등급을 `Unverifiable`. git 오류를 "추적 안 됨"으로 읽지 않는다 |
| 영속 백업 없음·바이트 불일치 | 그 대상은 고치지 않는다. 세션 임시 폴더나 자동 로드 폴더는 백업이 아니다 |
| 고친 뒤 검증 실패 | 완료라고 하지 않는다. 이번 변경만 정확히 되돌릴 수 있으면 되돌리고 `partial`, 아니면 멈추고 상태를 보고한다. 뒤 등급은 진행하지 않는다 |
